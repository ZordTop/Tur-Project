# Единый контракт данных (Data Contract) — Tur-Project
  

---

## 1. Таблица `users` (Пользователи и права)

Отвечает за регистрацию, вход, запоминание пользователя, блокировку и разделение на 3 режима работы.

| Поле | Тип данных | Обязательно | Описание и допустимые значения |
| :--- | :--- | :--- | :--- |
| `id` | `INTEGER` (PK, Auto) | Да | Уникальный ID пользователя |
| `email` | `VARCHAR(255)` (Unique) | Да | Логин для входа в систему |
| `password_hash` | `VARCHAR(255)` | Да | Зашифрованный пароль (никогда не отдаём во фронтенд) |
| `full_name` | `VARCHAR(150)` | Да | ФИО пользователя (подставляется при бронировании) |
| `phone` | `VARCHAR(30)` | Да | Телефон для связи |
| `role` | `VARCHAR(20)` | Да | Роль: `'user'` (по умолчанию), `'manager'`, `'admin'` |
| `is_blocked` | `BOOLEAN` | Да | Статус бана: `false` (активен, по умолчанию), `true` (заблокирован) |
| `created_at` | `TIMESTAMP` | Да | Дата и время регистрации |

## 2. Таблица `tours` (Единые пакетные туры)

Каждое свойство тура вынесено в отдельную колонку. Это позволяет мгновенно фильтровать туры по любым параметрам и автоматически складывать итоговую цену.

| Поле | Тип данных | Обязательно | Описание и допустимые значения |
| :--- | :--- | :--- | :--- |
| `id` | `INTEGER` (PK, Auto) | Да | Уникальный ID тура |
| `title` | `VARCHAR(200)` | Да | Название тура (например: «Солнечный Сочи: отдых у моря») |
| `description` | `TEXT` | Да | Описание программы тура |
| `image` | `VARCHAR(255)` | Да | Путь к картинке, например: `/images/sochi.jpg` |
| `rating` | `DECIMAL(2,1)` | Нет | Рейтинг тура от `1.0` до `5.0` |
| `nights` | `INTEGER` | Да | Продолжительность тура в ночах (для фильтра) |
| **Блок 1: Перелёт** | | | |
| `departure_city` | `VARCHAR(100)` | Да | Город вылета (например: `'Москва'`) |
| `destination_country` | `VARCHAR(100)` | Да | Страна прилёта (для фильтра по месту) |
| `destination_city` | `VARCHAR(100)` | Да | Город / курорт прилёта (совпадает с городом отеля) |
| `departure_at` | `TIMESTAMP` | Да | Дата и время вылета (для фильтра по дате) |
| `arrival_at` | `TIMESTAMP` | Да | Дата и время прилёта |
| `flight_duration` | `VARCHAR(50)` | Да | Время всего полёта (например: `'2ч 40мин'` или в минутах `160`) |
| `flight_class` | `VARCHAR(30)` | Да | Класс полёта: `'economy'` (Эконом), `'comfort'` (Комфорт), `'business'` (Бизнес) |
| `flight_price` | `INTEGER` | Да | Стоимость перелёта в рублях |
| **Блок 2: Отель** | | | |
| `hotel_name` | `VARCHAR(150)` | Да | Название отеля (находится в `destination_country`, `destination_city`) |
| `hotel_stars` | `INTEGER` | Да | Звёздность отеля: `2`, `3`, `4` или `5` (для фильтра) |
| `hotel_meal` | `VARCHAR(30)` | Да | Тип питания: `'RO'` (без питания), `'BB'` (завтраки), `'HB'` (полупансион), `'AI'` (всё включено) |
| `hotel_price` | `INTEGER` | Да | Стоимость проживания за весь срок в рублях |
| **Блок 3: Трансфер** | | | |
| `transfer_type` | `VARCHAR(30)` | Да | Тип трансфера: `'bus'` (общий автобус) или `'private'` (личный автомобиль) |
| `transfer_price` | `INTEGER` | Да | Стоимость трансфера в рублях |
| **Итог и Статус** | | | |
| `total_price` | `INTEGER` | Да | **Итоговая цена тура** (`flight_price + hotel_price + transfer_price`) |
| `is_active` | `BOOLEAN` | Да | Показывать ли тур в каталоге (`true` — активен, `false` — скрыт/архив) |


## 3. Таблица `bookings` (Заявки на бронирование)

Универсальная таблица: подходит и для самостоятельной брони клиентом на сайте, и для оформления живого клиента через интерфейс менеджера.

| Поле | Тип данных | Обязательно | Описание и допустимые значения |
| :--- | :--- | :--- | :--- |
| `id` | `INTEGER` (PK, Auto) | Да | Уникальный номер заявки |
| `tour_id` | `INTEGER` (FK -> `tours.id`) | Да | Какой тур забронирован |
| `user_id` | `INTEGER` (FK -> `users.id`) | Нет | ID клиента (если бронировал сам; `NULL`, если оформил менеджер) |
| `manager_id` | `INTEGER` (FK -> `users.id`) | Нет | ID менеджера, который оформил заявку (`NULL`, если клиент сам) |
| `client_name` | `VARCHAR(150)` | Да | ФИО реального туриста (из профиля или вводится менеджером) |
| `client_phone` | `VARCHAR(30)` | Да | Телефон туриста |
| `comment` | `TEXT` | Нет | Пожелания клиента или заметка менеджера |
| `status` | `VARCHAR(20)` | Да | Статус: `'new'` (новая), `'confirmed'` (подтверждена), `'cancelled'` (отменена) |
| `created_at` | `TIMESTAMP` | Да | Дата и время создания брони |

## 4. Контракт маршрутов и переменных для Фронтенда (EJS)

Чтобы фронтендер мог верстать шаблоны параллельно с разработкой бэкенда, сервер обязуется передавать в `res.render(...)` строго следующие объекты:

1. **Во все шаблоны (глобально через `res.locals`):**
   - `currentUser` — объект текущего пользователя (`{ id, email, full_name, phone, role }`) или `null`, если пользователь не вошёл.

2. **Страница каталога (`GET /tours` -> `views/tours.ejs`):**
   - `tours` — массив объектов из таблицы `tours`.
   - `filters` — объект текущих выбранных фильтров `{ country, city, maxPrice, nights, hotelStars }` (чтобы значения не сбрасывались в форме после поиска).

3. **Личный кабинет клиента (`GET /profile` -> `views/profile.ejs`):**
   - `bookings` — массив броней пользователя (с подтянутым названием тура `tour_title` и ценой `total_price`).

4. **Панель менеджера (`GET /manager` -> `views/manager.ejs`):**
   - `tours` — список туров (отфильтрованный по запросу менеджера).
   - `recentBookings` — последние заявки, оформленные этим менеджером.

5. **Панель админа (`GET /admin` -> `views/admin.ejs`):**
   - `tours` — все туры (включая скрытые `is_active = false`).
   - `bookings` — все заявки всех клиентов и менеджеров.
   - `users` — список всех пользователей для управления ролями и блокировками.
